# WordGloss（生词注释）

给 KOReader 的英文书做**词级生词注释**：把生词的中文释义直接注在词的上方（或下方），
效果类似 Kindle 的 Word Wise。**原书一个字节都不改**——不加 ruby、不改 XHTML，
生成的释义只存在于插件自己的缓存与渲染层里。

当前版本 **1.8.9**（与 `_meta.lua` 一致）。

**[简体中文](README.zh-CN.md) | [English](README.md)**

## 特点

- **不修改原书**：EPUB 存档、`.sdr`、书签、阅读进度全都不动。清除插件数据即可完全复原。
- **默认不自动运行**：装好之后打开书**什么都不会发生**。需要你在菜单里点
  「开始转换」，并自己选词汇量与翻译范围，插件才开始工作（联网也只在此时发生）。
- **显示与转换分开**：新增「显示注释生词」勾选框，与「开始转换」互不干扰——
  取消勾选时注释和为它预留的行距一起撤掉，已缓存的释义一条不删，重新勾选立刻恢复。
- **词汇量分级**：初级 / 中级 / 高级，按语料库词频排名决定"哪些词值得注释"
  （初级 = 不注释最常见的 1500 词，中级 3000，高级 5000），也可以自定义。
- **内置离线词典（默认）**：随插件带一份裁剪过的 ECDICT 释义包（约 4 MB），
  41,145 个原形 + 35,863 个变形，**92% 带词性**。对插件自己那 39,301 词的词表**覆盖率
  100%**（51% 直接命中、49% 走变形回查，只剩 8 个词漏网）。整本书几秒钟翻完，
  **完全不联网**；选「仅本地」则一个网络请求都不发。
- **在线只做兜底**：词典里没有的词（生造词、人名地名、新潮词）才走 Edge 免费接口，
  无需 API key。两者写进同一个 SQLite 缓存、跨书复用，一个词只翻一次，之后翻页秒出。
  「释义来源」可切 `本地优先`（默认）/ `仅本地` / `仅在线`。
- **在线引擎可换**：默认 Edge（免费、免密钥），也可以在「翻译生词设置 → 联网设置」
  里换成 Google翻译、智谱GLM-4 Flash、硅基流动、DeepL、DeepSeek 或任意 OpenAI 兼容服务。
- **词性有就带、没有就空**：本地词典带 `adj.` / `n.` / `vt.`，在线接口实测不返回
  （抽样 22 词 0 命中）。所以「显示词性」（默认关）打开后是**有就显示、没有就空着**，
  同一页会混排——这是有意的，不为了整齐去编一个。
- **一键补齐词性**：老版本缓存里的释义在清洗时被剥掉了词性，
  `清除注释数据 → 用本地词典补齐词性（不联网）` 可以离线补回来，不动释义本身。
- **手动翻译 + 可选后台翻译**：可以在菜单里翻译当前章或整本书（子进程执行，
  翻译时照样翻页，可随时停止）。另有「阅读时自动补翻译」开关，**默认关**。
- **专名过滤**：只以大写出现过的词（人名、地名）默认不注释。
- **注释位置可调**：`词上方小字` / `词下方小字`（顺序是 词→下划线→注释）二选一；
  「注释偏移」控制注释离单词多远（正 = 推离单词，负 = 压近词身），「下划线偏移」
  同理控制下划线离单词多远；偏移变大时行距会自动加大，不会压到相邻行。
- **下划线样式可调**：实线 / 虚线 / 波浪线，粗细 1~6 px；虚线与波浪线共用一份
  「线的密度」（数值越小越密）。密度除小/中/大三档外还有 **自定义**（2~24 px，
  虚线 = 一段实线的长度，波浪线 = 半个波的宽度）。波浪线按 custombg 那种平缓画法：
  一个完整波 12~22 px、振幅只有 2 px，且**不跟着线粗涨**，粗细调大也不会变成锯齿。
- **插件自带更新**：`关于 → 检查更新` 会去 GitHub Release 问一次，有新版本时
  可选「只更新代码（几十 KB）」或「完整包（含离线词典）」，下载后先**核对体积**（挡住
  下载被截断、代理返回错误页），拿得到摘要再**比对 SHA-256**（挡住镜像篡改），
  **旧版本先备份**、装完问一句要不要重启。默认只在手动点的时候联网，
  也可以打开「每天自动检查一次」（只提醒，不会自己装）。
- **不依赖大词典**：随插件只有两个小包——1.5 MB 的词频包（排名 + 词形还原）和
  上面那个约 4 MB 的释义包，都是从 ECDICT 按"本插件真正会注释的词"裁出来的，
  不像某些方案需要几百 MB 的本地词典库。

## 安装

1. 下载 `wordgloss-1.8.9.zip`（完整包，含离线词典）或 `wordgloss-1.8.9-code.zip`
   （只有代码，**本地已经有词典时用它就够**），两者都在 Release 里。
2. 解压/复制到 KOReader 的 `plugins/` 目录，最终结构必须是：

   ```
   <koreader>/plugins/wordgloss.koplugin/main.lua
   <koreader>/plugins/wordgloss.koplugin/_meta.lua
   <koreader>/plugins/wordgloss.koplugin/data/wordgloss_en.sqlite3
   <koreader>/plugins/wordgloss.koplugin/data/wordgloss_gloss_en.sqlite3
   ```

   第二个文件是离线释义包。少了他插件照样能用，只是每个词都要走联网翻译。

   最常见的问题是**多套了一层目录**（`plugins/wordgloss.koplugin/wordgloss.koplugin/main.lua`），
   这时 KOReader 视同这个插件不存在。
3. **完全退出并重启 KOReader**（不是返回书架，是彻底退出进程）。
4. 打开一本 EPUB → 顶部菜单栏 → **工具** 页签 → **WordGloss**。

各平台 `plugins/` 位置：

| 平台 | plugins/ 目录 |
| --- | --- |
| Kindle | `/mnt/us/koreader/plugins/` |
| Android | `/storage/emulated/0/koreader/plugins/` |
| Linux / macOS / Windows | KOReader 解压目录下的 `koreader/plugins/` |

### 菜单里找不到插件？

KOReader 用 `pcall` 包住插件实例化：`init()` 里抛任何异常都不会弹窗，只在日志里留一行，
插件从此**静默消失**。按顺序排查：

1. 目录结构是否如上（没有多套一层）。
2. 打开 `koreader/crash.log`，搜 `wordgloss`：
   - `Failed to initialize wordgloss plugin: ...` → `init()` 抛的原始错误；
   - `Error when loading .../wordgloss.koplugin/main.lua` → `main.lua` 根本没加载成功。
3. 是否彻底重启过 KOReader 进程（返回书架不算）。

> 1.0.0 就踩过这个坑：菜单构建时用一个叫 `_` 的循环变量遮蔽了 gettext 函数，
> `init()` 抛异常 → 菜单里什么都看不到。1.0.1 已修复，并加了兜底菜单：
> 即使菜单构建失败，「工具」里也会留一个入口并显示出错原因。

## 使用

菜单 **顶部菜单栏 → 工具 页签 → WordGloss**。默认状态下插件是**关闭**的，
打开书时它不会做任何事，按下面的顺序手动开一次即可：

1. **词汇量** —— 先选好尺子：初级（不注释最常见的 1500 词）/ 中级（3000）/
   高级（5000），或自定义（都在次级菜单里）。
2. **开始转换** —— 点进去，再点第一行的「开始转换」开关，这才是真的开始注释。
   随后会问一句翻译范围：`翻译本章` / `翻译整本（后台）` / `只用已有释义` / `停止转换`。
3. 同一层里的 **显示注释生词** 决定要不要把注释画到书页上。取消勾选只是**隐藏**
   （注释和为它预留的行距都会撤掉，但数据一条都不删），重新勾选立刻回来。
   释义缓存**跨书共享**，所以这一项不看「开始转换」的开关状态，只看缓存里有没有
   可显示的释义：昨天转过的词（哪怕是在别的书里转的）直接勾上就能显示，**不用每本
   书、每次开机都重新转换一遍**；只有一条释义都没有时才会提示先点「开始转换」。

主菜单只有七个入口，所有设置都收在对应的入口里：

| 菜单项 | 说明 |
| --- | --- |
| **开始转换** | 分组入口：里面是「开始转换 / 停止转换」开关（打勾 = 已开始），以及「显示注释生词」勾选框。 |
| **词汇量** | 初级 1500 / 中级 3000 / 高级 5000，或自定义。 |
| **注释设置** | 注释本身的所有设置，见下表。 |
| **下划线设置** | 下划线的所有设置，见下表。 |
| **翻译生词设置** | 先有「联网设置」（选在线引擎与密钥），再有「释义来源」（本地优先 / 仅本地 / 仅在线），再是翻译当前章 / `翻译整本书的生词（增量）` / `重新翻译整本（覆盖已有）`——**增量只补没译过的，覆盖已有会把已译好的重翻一遍**（本地优先下会用词典释义替换掉在线译文），另有「阅读时自动补翻译生词（需要联网）」开关（默认关）。**「查看翻译进度」与「停止翻译」只在后台有翻译任务时才出现在菜单里**——平时不占位置；翻译整本书时把进度窗关掉后，来这里看进度条或中止任务。 |
| **清除注释数据** | 维护用：`清除本书注释数据`（清完本书的注释会消失，重新翻译后才再显示；释义缓存保留，其它书照用）/ `清空全部注释数据`（删掉所有书已翻译的释义）/ `用本地词典补齐词性（不联网）`。 |
| **关于** | 版本号、作者、小红书ID、`检查更新`（见下）、`重装离线词典`（见下）、`每天自动检查一次` 开关。 |

### 更新插件

`关于 → 检查更新` 做这些事（联网只读，装不装由你点）：

1. 问一次 GitHub Release（直连不通时自动换 `gh-proxy` 等镜像）。
2. 有新版本时弹出版本号与更新说明，让你选：
   - **只更新代码**（几十 KB）：本地两个离线数据包都在时用这个（**已有的 `data/`
     会自动搬到新版本里**，不会被换名流程一起带走）；
   - **完整包**（含离线词典，约 3 MB）：任一个数据包缺失、或想顺便换一份时用。
   说明太长时只显示前几行，剩下的放在 `查看完整更新说明` 里（那个窗口可以滚动），
   按钮不会被说明挤到屏幕外。
3. 下载后先与 Release API 给的**字节数**比对（最可信，挡住截断与错误页）；
   再尝试取 `.sha256`，**拿得到就比对**，拿不到就跳过（镜像没同步也不卡住用户）。
4. 旧目录整个改名成 `wordgloss.koplugin.backup`，新版本换名进来——
   **换名失败会立刻换回去**；备份留到"新版本启动成功"之后才删，
   所以万一新版本根本加载不起来，把 `.backup` 改回 `wordgloss.koplugin` 就是原样。
5. 装完问一句要不要重启 KOReader（不重启就还是旧版本）。

「每天自动检查一次」默认关。打开后每天第一次打开书时静默问一次，
**只提示、不自动下载**，免得读到一半被打断。

### 离线词典丢了怎么办

`data/` 里那两个包（词频包 + 离线释义包）只随**完整包**分发。缺任意一个，
翻译整本书都会直接失败（报"词频包缺失，没法判断生词"），因为判断哪些词算生词
全靠词频包。

自助修复：`关于 → 重装离线词典`。它会**不管当前版本号是多少**，直接拉最新的完整包
覆盖装上（约 3 MB），已翻译的释义缓存不会丢。词典缺失时，这一行会自己变成
`重装离线词典（当前缺失，翻译会失败）`。另外「检查更新」也会在发现本地词典不全时
自动改用完整包，不会再给一个"装完依旧不能用"的选项。

**注释设置**里依次是：

| 菜单项 | 说明 |
| --- | --- |
| 注释样式 | `词上方小字`（默认）或 `词下方小字`（词 → 下划线 → 注释）。 |
| 注释字体 | 默认`跟随KOReader`（用 KOReader 的 CJK 字体）；点 `选择字体…` 会打开文件浏览，自己挑一个 `.ttf` / `.otf` / `.ttc`（**长按文件名**选中）。要选带汉字字形的字体，否则注释全是方框。 |
| 注释字号 | 8~24 px。 |
| 每页注释上限 | 一页生词太多时优先注释最生僻的；0 = 不限。 |
| 释义长度上限 | 按字符数截断，保证注释能塞进两行之间（离线与在线用同一套截断规则）。 |
| 注释偏移 | 注释离单词多远，-20~40 px。正 = 推离单词（上方模式往上、下方模式往下），负 = 压近词身。 |
| 显示词性 | 默认关。打开后在注释前加 `adj.` / `n.` / `vt.`。**只有本地词典有词性，在线翻译没有**，所以同一页会有的带、有的不带——有就显示，没有就空着。 |
| 不注释人名/地名 | 默认开。全书里只以大写出现过的词（人名、地名）会被跳过。 |

**下划线设置**里依次是：

| 菜单项 | 说明 |
| --- | --- |
| 显示下划线 | 注释往往比词宽，下划线用来指明它属于哪个词。 |
| 下划线样式 | 实线 / 虚线 / 波浪线 + 粗细 1~6 px + **线的密度**（只对虚线、波浪线生效：小（疏）/ 中 / 大（密）/ **自定义** 2~24 px，越小越密）。 |
| 下划线偏移 | 下划线离单词多远，-20~40 px。正 = 往下推远、负 = 贴近词身。 |

`翻译本章 / 翻译整本` 会弹出可收起的进度条（点窗口外部即收起，继续读不受影响）；
窗口只有标题和进度条，进度每增加 2% 才重绘一次（不再一秒闪两下）。
翻译完成后翻页即可见注释。没有释义的生词不会显示，也不会因此卡住阅读。

两种模式都会注入一条 `line-height` 给注释腾出行间空间，所以开始/停止时
书会重新排版一次——这是为了让注释有地方画，注释本身不占正文的位置。
`词上方小字` 按"注释高度 + 注释偏移"与"下划线偏移 + 线的高度"里**更大的一边**算行距；
`词下方小字` 里注释与下划线叠在同一侧，两边**相加**（夹在 1.5~4.0）。
所以偏移调大、线调粗、换成波浪线时行距都会自动跟着长，不会被相邻的行压住。

## 原理

1. **判断哪些词是生词**
   数据包 `data/wordgloss_en.sqlite3` 只有一张表 `lex(word, rank, base)`：
   `rank` 是语料库词频排名（1 = the），`base` 是变形词的原形（`took` → `take`）。
   判定规则：先规范词形（去标点、撇号取词干、忽略 `don't` 这类缩写词干），
   再查原形排名——排名在阈值之内视为"已掌握"，不注释；超出阈值或不在包内即为生词。
   词形不在包内时还会按后缀规则回退（`stopped` → `stop`），只有回退结果确实是常见词才采纳。

2. **取释义**
   `wordgloss_providers.lua` 调 Edge 免费接口（批量 ≤ 12 条 / ≤ 4000 字节，
   整块失败自动降级逐条）。翻译的是**原形**，所以 `took`/`taken`/`takes` 共用一条释义。
   结果经 `wordgloss_gloss.lua` 精简（只取第一行、去掉译文里偶发的词性前缀与括号补充、
   按字符数截断、去掉首尾标点），存入缓存；**翻译失败也存一条空记录**，避免反复重试同一个词。

3. **预取**
   `wordgloss_epub.lua` 解包 EPUB、按 spine 找到章节，用段落级扫描取出每章的词
   （不依赖渲染结果），`wordgloss_prefetch.lua` 在**子进程**里逐章翻译并把结果写进缓存。
   进度通过进度文件回传、取消用哨兵文件通知子进程，所以整书翻译时阅读界面不受影响。

4. **显示**
   `wordgloss_page.lua` 用 CREngine 的 `getPageXPointer` / `getNextVisibleWordStart|End`
   / `getTextFromXPointers` 逐词走动，用 `getScreenBoxesFromPositions` 取屏幕坐标；
   `wordgloss_overlay.lua` 注册成 ReaderView 的 view module，把注释画在词的上方
   （`词上方小字`）或下划线的下方（`词下方小字`）。同一行放不下时舍掉最常见的词、
   保留最生僻的；行间空间由注入的 `line-height` 提供。

## 重新生成数据包

两个数据包都由 `tools/` 下的脚本生成，源数据同样是 ECDICT 的 `test.db`
与 Stardict 的 `lemma.en.txt`（词形还原）：

```sh
# 词频包：排名 + 原形（1.5 MB）
python tools/build_en_db.py --dict test.db --lemma lemma.en.txt \
    --out data/wordgloss_en.sqlite3 --max-rank 20000

# 释义包：中文释义 + 词性（约 4 MB，1.5.0 起随插件分发）
python tools/build_gloss_db.py --dict test.db --lemma lemma.en.txt \
    --out data/wordgloss_gloss_en.sqlite3

python tools/check_pack.py     # 抽查若干词的排名与词形，校验词频包
```

- 词频包：排名 ≤ 20000 的词进包，其余（含包内不存在的词）一律按"超纲生词"处理。
- 释义包：取 `frq > 0` 的全部纯小写字母词（41,145 个），把 ECDICT 的多行
  translation 摊平成一个义项列表（剥掉词性前缀、`[医]`/`<法>` 这类括注、
  缩写全称里的英文部分），只保留前 6 个义项；开头的词性单独存进 `pos` 列。
  **不要改成按词频包裁剪**——排名 > 20000 的那 2.4 万个极生僻词恰恰是插件
  最想注释的（`RANK_UNKNOWN` 必定命中生词判定），按词频包裁会正好漏掉它们。
- 许可：WordGloss 本身 GPL-3.0；数据包继承来源许可
  （ECDICT MIT，Stardict lemma.en.txt），见 `data/` 与 `tools/` 中的说明。
  790 MB 的原始 `test.db` **不随插件分发**，只在你电脑上当原料用。

## 发布新版本

`tools/release.py` 一条命令搞定打包与发布（不需要装 `gh`，走 GitHub API）：

```sh
python tools/release.py                  # 检查 + 打包 + 打印将要执行的命令（不动远程）
python tools/release.py --execute        # 真的打 tag、push、建 Release、传包
```

默认从 `_meta.lua` 读版本号（会顺带核对 `main.lua` 里的 `VERSION`），
产出 4 个文件到仓库的上一级目录：

| 文件 | 说明 |
| --- | --- |
| `wordgloss-<版本>.zip` | 完整包：代码 + `data/` 离线词典（约 3 MB） |
| `wordgloss-<版本>-code.zip` | 仅代码：不含 `data/`（约 100 KB） |
| 两个 `.zip.sha256` | 各自的 SHA-256，插件装包前会比对（拿不到则跳过） |

两个 zip 的顶层目录都是 `wordgloss.koplugin/`，解压进 `plugins/` 就是正确结构
（自动更新也按这个结构认）。`--execute` 需要 GitHub 令牌：

1. https://github.com/settings/tokens → **Generate new token (classic)**
2. 勾选 `public_repo`
3. `set GITHUB_TOKEN=ghp_xxx`（PowerShell 用 `$env:GITHUB_TOKEN="ghp_xxx"`），
   或者直接 `python tools/release.py --execute --token ghp_xxx`

发布前脚本会检查：工作区干净、在 `main` 分支、没有未推送的提交、远端没有同名 tag。
任一项不过就只打包、不发布。

纯 Lua 逻辑（生词判定、释义精简、注释排布、绘制层、行距注入、菜单）

`tests/dump_menu.lua` 会把真实菜单层级打印出来，用来确认入口文案和顺序：

  ① 换名更新是整个目录一起走，`data/`（词频包 + 离线释义包）本来就不在 code 包里，

## 已知限制与注意
- 只处理**英文**生词（语言包的词频与词形数据是英文的，分词也按空格切分）。
- 释义是机器翻译，**不区分词义**（多义词只给最常见的意思），是提示而非词典。
- 离线释义包覆盖 7.7 万个词形；包外的词（生造词、人名地名、新潮词）首次仍需联网
  取一次（且只在「释义来源」不是「仅本地」时），只发单词本身、不发正文。
- 专名过滤是基于"是否只以大写出现"的启发式；句首才出现一次的罕见词可能被漏标。
- 两种模式都会改变行距；如果对原书排版非常敏感，可以把注释字号调小、偏移调回 0。
