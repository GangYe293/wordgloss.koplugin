# WordGloss（生词注释）

给 KOReader 的英文书做**词级生词注释**：把生词的中文释义直接注在词的上方（或下方），
效果类似 Kindle 的 Word Wise。**原书一个字节都不改**——不加 ruby、不改 XHTML，
生成的释义只存在于插件自己的缓存与渲染层里。

当前版本 **1.3.0**（与 `_meta.lua` 一致）。

[English](README.md) | 简体中文

## 特点

- **不修改原书**：EPUB 存档、`.sdr`、书签、阅读进度全都不动。清除插件数据即可完全复原。
- **默认不自动运行**：装好之后打开书**什么都不会发生**。需要你在菜单里点
  「开始转换」，并自己选词汇量与翻译范围，插件才开始工作（联网也只在此时发生）。
- **词汇量分级**：初级 / 中级 / 高级，按语料库词频排名决定"哪些词值得注释"
  （初级 = 不注释最常见的 1500 词，中级 3000，高级 5000），也可以自定义阈值。
- **释义走 Edge 免费接口**：无需 API key，逐词翻译后落 SQLite 缓存，跨书复用；
  一个词只翻一次，之后翻页秒出、不用联网。
- **手动翻译 + 可选后台翻译**：可以在菜单里翻译当前章或整本书（子进程执行，
  翻译时照样翻页，可随时停止）。另有「阅读时自动补翻译」开关，**默认关**。
- **专名过滤**：只以大写出现过的词（人名、地名）默认不注释。
- **注释位置可调**：`词上方小字` / `词下方小字`（顺序是 词→下划线→注释）二选一；
  「注释偏移」控制注释离单词多远（正 = 推离单词，负 = 压近词身），「下划线偏移」
  同理控制下划线离单词多远；偏移变大时行距会自动加大，不会压到相邻行。
- **下划线样式可调**：实线 / 虚线 / 波浪线，粗细 1~6 px；虚线与波浪线共用一份
  「线的密度」（数值越小越密）。密度除小/中/大三档外还有 **自定义**（2~24 px，
  虚线 = 一段实线的长度，波浪线 = 半个波的宽度）。波浪线按 custombg 那种平缓画法：
  一个完整波 12~22 px、振幅只有 2 px，且**不跟着线粗涨**，粗细调大也不会变成锯齿。
- **不依赖大词典**：内置语言包只有约 1.5 MB（词频排名 + 词形还原），
  不像某些方案需要几百 MB 的本地词典库。

## 安装

1. 下载 `wordgloss.koplugin-v1.3.0.zip`（或直接用本目录）。
2. 解压/复制到 KOReader 的 `plugins/` 目录，最终结构必须是：

   ```
   <koreader>/plugins/wordgloss.koplugin/main.lua
   <koreader>/plugins/wordgloss.koplugin/_meta.lua
   <koreader>/plugins/wordgloss.koplugin/data/wordgloss_en.sqlite3
   ```

   最常见的问题是**多套了一层目录**（`plugins/wordgloss.koplugin/wordgloss.koplugin/main.lua`），
   这时 KOReader 视同这个插件不存在。
3. **完全退出并重启 KOReader**（不是返回书架，是彻底退出进程）。
4. 打开一本 EPUB → 顶部菜单栏 → **工具** 页签 → **生词注释（WordGloss）**。

各平台 `plugins/` 位置：

| 平台 | plugins/ 目录 |
| --- | --- |
| Kindle | `/mnt/us/koreader/plugins/` |
| Android | `/storage/emulated/0/koreader/plugins/` |
| Linux / macOS / Windows | KOReader 解压目录下的 `koreader/plugins/` |

### 菜单里找不到插件？

KOReader 用 `pcall` 包住插件实例化：`init()` 里抛任何异常都不会弹窗，只在日志里留一行，
插件从此**静默消失**。按顺序排查：

1. 目录结构是否如上（没有多套一层）。
2. 打开 `koreader/crash.log`，搜 `wordgloss`：
   - `Failed to initialize wordgloss plugin: ...` → `init()` 抛的原始错误；
   - `Error when loading .../wordgloss.koplugin/main.lua` → `main.lua` 根本没加载成功。
3. 是否彻底重启过 KOReader 进程（返回书架不算）。

> 1.0.0 就踩过这个坑：菜单构建时用一个叫 `_` 的循环变量遮蔽了 gettext 函数，
> `init()` 抛异常 → 菜单里什么都看不到。1.0.1 已修复，并加了兜底菜单：
> 即使菜单构建失败，「工具」里也会留一个入口并显示出错原因。

## 使用

菜单 **顶部菜单栏 → 工具 页签 → 生词注释（WordGloss）**。默认状态下插件是**关闭**的，
按下面的顺序手动开一次即可：

1. **词汇量（初级/中级/高级）** —— 先选好尺子：初级（不注释最常见的 1500 词）/
   中级（3000）/ 高级（5000），或自定义阈值。
2. **开始转换（注释生词）** —— 点它才会开启注释。随后会问一句翻译范围：
   `翻译本章` / `翻译整本（后台）` / `只用已有释义` / `停止转换`。
3. 之后翻页即带注释。想关掉就点同一位置的 **停止转换（隐藏注释）**。

| 菜单项 | 说明 |
| --- | --- |
| 开始转换 / 停止转换 | 手动总开关。**默认关闭**，插件不会自己在打开书时跑起来。 |
| 词汇量（初级/中级/高级） | 初级 1500 / 中级 3000 / 高级 5000，或自定义阈值。 |
| 注释样式 | `词上方小字`（默认）或 `词下方小字`（词 → 下划线 → 注释）。 |
| 注释字号 / 释义长度上限 / 每页注释上限 | 调注释的视觉密度（一页生词太多时优先注释最生僻的）。 |
| 用下划线标出被注释的词 | 注释比词宽，下划线用来指明它属于哪个词。 |
| 下划线样式 | 实线 / 虚线 / 波浪线 + 粗细 1~6 px。 |
| 线的密度 | 只对虚线、波浪线生效：小（疏）/ 中 / 大（密）/ **自定义**（2~24 px，越小越密）。 |
| 注释偏移 | 注释离单词多远，-20~40 px，正 = 推离单词（上方模式往上、下方模式往下），负 = 压近词身。 |
| 下划线偏移 | 下划线离单词多远，-20~40 px，正 = 往下推远、负 = 贴近词身。 |
| 不注释人名/地名 | 默认开启。 |
| 注释字体 | 默认跟随 KOReader 的 CJK 字体；若显示成方块可手动指定字体名。 |
| 翻译生词（联网） | 翻译当前章 / 翻译整本书 / 查看进度 / 停止，另有「阅读时自动补翻译生词」开关（默认关）。 |
| 清除本书注释数据 / 清空全部释义缓存 | 维护用。 |
| 状态 | 显示"是否已开始、词汇量档位、已缓存多少条释义"。 |

`翻译本章 / 翻译整本` 会弹出可收起的进度条（点窗口外部即收起，继续读不受影响）；
窗口只有标题和进度条，进度每增加 2% 才重绘一次（不再一秒闪两下）。
翻译完成后翻页即可见注释。没有释义的生词不会显示，也不会因此卡住阅读。

两种模式都会注入一条 `line-height` 给注释腾出行间空间，所以开始/停止时
书会重新排版一次——这是为了让注释有地方画，注释本身不占正文的位置。
`词上方小字` 按"注释高度 + 注释偏移"与"下划线偏移 + 线的高度"里**更大的一边**算行距；
`词下方小字` 里注释与下划线叠在同一侧，两边**相加**（夹在 1.5~4.0）。
所以偏移调大、线调粗、换成波浪线时行距都会自动跟着长，不会被相邻的行压住。

| 释义缓存 / 每本书状态 | KOReader 数据目录 `wordgloss.sqlite3`（WAL） |
| 预取进度与取消标记 | KOReader 数据目录 `cache/wordgloss/` |
| 设置 | KOReader 原生 `settings.reader.lua`（`wordgloss_` 前缀） |

## 原理

1. **判断哪些词是生词**
   数据包 `data/wordgloss_en.sqlite3` 只有一张表 `lex(word, rank, base)`：
   `rank` 是语料库词频排名（1 = the），`base` 是变形词的原形（`took` → `take`）。
   判定规则：先规范词形（去标点、撇号取词干、忽略 `don't` 这类缩写词干），
   再查原形排名——排名在阈值之内视为"已掌握"，不注释；超出阈值或不在包内即为生词。
   词形不在包内时还会按后缀规则回退（`stopped` → `stop`），只有回退结果确实是常见词才采纳。

2. **取释义**
   `wordgloss_providers.lua` 调 Edge 免费接口（批量 ≤ 12 条 / ≤ 4000 字节，
   整块失败自动降级逐条）。翻译的是**原形**，所以 `took`/`taken`/`takes` 共用一条释义。
   结果经 `wordgloss_gloss.lua` 精简（只取第一行、去掉译文里偶发的词性前缀与括号补充、
   按字符数截断、去掉首尾标点），存入缓存；**翻译失败也存一条空记录**，避免反复重试同一个词。

3. **预取**
   `wordgloss_epub.lua` 解包 EPUB、按 spine 找到章节，用段落级扫描取出每章的词
   （不依赖渲染结果），`wordgloss_prefetch.lua` 在**子进程**里逐章翻译并把结果写进缓存。
   进度通过进度文件回传、取消用哨兵文件通知子进程，所以整书翻译时阅读界面不受影响。

4. **显示**
   `wordgloss_page.lua` 用 CREngine 的 `getPageXPointer` / `getNextVisibleWordStart|End`
   / `getTextFromXPointers` 逐词走动，用 `getScreenBoxesFromPositions` 取屏幕坐标；
   `wordgloss_overlay.lua` 注册成 ReaderView 的 view module，把注释画在词的上方
   （`词上方小字`）或下划线的下方（`词下方小字`）。同一行放不下时舍掉最常见的词、
   保留最生僻的；行间空间由注入的 `line-height` 提供。

## 重新生成语言包

数据包由 `tools/build_en_db.py` 生成，源数据是 ECDICT 的 `test.db`（词频字段 `frq`）
与 Stardict 的 `lemma.en.txt`（词形还原）：

```sh
python tools/build_en_db.py --dict test.db --lemma lemma.en.txt \
    --out data/wordgloss_en.sqlite3 --max-rank 20000
python tools/check_pack.py     # 抽查若干词的排名与词形，校验数据包
```

- 排名 ≤ 20000 的词进包，其余（含包内不存在的词）一律按"超纲生词"处理。
- 许可：WordGloss 本身 GPL-3.0；数据包继承来源许可
  （ECDICT MIT，Stacheldict lemma.en.txt），见 `data/` 与 `tools/` 中的说明。

## 测试

纯 Lua 逻辑（生词判定、释义精简、注释排布、绘制层、行距注入、菜单）
都能离线跑，不需要 KOReader 也不需要装 Lua（用 fengari = JS 里的 Lua VM）：

测试放在**工作区根的 `tests/wordgloss/`**（不在插件目录里——插件目录会被当成
"只要运行时文件"清理掉，测试放里面会反复丢失），桩在 `tests/wordgloss/stubs/`。

```sh
# fengari runner（Node 里的 Lua VM）
NODE=node                                       # 或你的 node 可执行文件
RUNNER=/path/to/luatest/runlua.js
T=/absolute/path/to/tests/wordgloss             # 两个参数都要绝对路径
"$NODE" "$RUNNER" "$T" "$T/run_tests.lua"       # 纯逻辑 + 绘制层：51 项
"$NODE" "$RUNNER" "$T" "$T/run_load_test.lua"   # 13 个模块能否装载
"$NODE" "$RUNNER" "$T" "$T/dump_menu.lua"       # 打印真实菜单层级与文案
```

脚本从 `arg[0]` 反推工作区根，再拼出插件目录，所以在别的机器上只要目录结构一致就能跑。

`tests/run_load_test.lua` 专门复现 KOReader 装载插件的真实过程
（`dofile(main.lua)` → `pcall(plugin.new, ...)` → `registerToMainMenu`），
把菜单里所有 `text_func` / `checked_func` 都真调用一遍 —— 上面那个"菜单里看不见插件"
的问题就是它抓出来的；1.1.0 的"默认不自动运行"也由它守着
（未启用时不许画注释、不许发起翻译）。改完 `main.lua` / `wordgloss_ui.lua` 后两套都要跑。

`tests/dump_menu.lua` 会把真实菜单层级打印出来，用来确认入口文案和顺序：

```sh
node runlua.js <tests/wordgloss> <tests/wordgloss>/dump_menu.lua
```

`tests/wordgloss/stubs/` 里是 KOReader 模块的最小桩（由 `make_stubs.py` 生成），
测试脚本会自己把它们加进 `package.path`。

## 版本变化

- **1.3.0**：**重画波浪线**（原来波长只有 4~8 px、振幅还跟着线粗涨，画出来是锯齿）。
  改成 custombg.koplugin 那种平缓画法：一个完整波 12~22 px，振幅固定 1~2 px
  （只跟波长走，线调粗也不会变陡）。**「线的密度」新增 `自定义` 档**：以像素为单位
  填 2~24（虚线 = 一段实线的长度，波浪线 = 半个波的宽度），数值越小越密；
  预设三档对应 11 / 6 / 3 px。
- **1.2.1**：修掉**断词换行时第二行没有下划线**的问题。一个词被拆到两行显示时，
  CREngine 会给出多个屏幕盒子，之前只取了第一个，所以注释正常显示、下划线却只画在
  第一行的那半截上。现在每个盒子都会各画一条（虚线/波浪线、偏移、粗细都各自生效），
  注释仍然只画一次。
- **1.2.0**：去掉「段落下方生词表」模式，换成 **`词下方小字`**（顺序 词→下划线→注释）；
  「词上方小字（Word Wise 风格）」改名为 `词上方小字`。下划线新增 **波浪线**，
  虚线与波浪线都多了 **线的密度**（小/中/大，大 = 更密）。行距计算按模式分成
  "取大边"与"两边相加"两种，波浪线的波峰波谷也计入行距。

- **1.1.0**：改为**手动启动**。插件默认关闭，不再在打开书时自动运行；
  新增菜单首项「开始转换（注释生词）」，词汇量（初级/中级/高级）提到第二项；
  「生词预取」改名为「翻译生词（联网）」，并新增默认关闭的「阅读时自动补翻译生词」开关；
  自动触发的翻译**不再弹进度窗**（1.0.x 里它会一闪而过）。
- **1.0.1**：修掉菜单构建时的 `_` 遮蔽 bug（插件曾在菜单里静默消失），补兜底菜单与装载测试。
- **1.0.0**：首个版本。

## 已知限制与注意
- 只处理**英文**生词（语言包的词频与词形数据是英文的，分词也按空格切分）。
- 释义是机器翻译，**不区分词义**（多义词只给最常见的意思），是提示而非词典。
- 需要联网才能首次取得释义（只发单词本身，不发正文）。
- 专名过滤是基于"是否只以大写出现"的启发式；句首才出现一次的罕见词可能被漏标。
- 两种模式都会改变行距；如果对原书排版非常敏感，可以把注释字号调小、偏移调回 0。
